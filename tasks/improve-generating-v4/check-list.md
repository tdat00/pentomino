until their prerequisites exist (T11c); the stage-4 plan is generated at the activation of its collection (T11e).

**The idle declaration** (how "difficulty-v3 has nothing scheduled" is established). Only the owner knows Sudoku's
difficulty-v3 schedule. When he states that it has nothing scheduled until a time T, at most 24 h ahead, the
orchestrator writes the declaration, notes it in the Execution log of the running task, and deletes the file as soon as

```powershell
$now = [DateTime]::UtcNow
[ordered]@{ format = 'dv3-idle'; version = 1; setAt = $now.ToString('o'); idleUntil = $now.AddHours(<hours to T>).ToString('o');
  setBy = 'orchestrator for the owner'; source = '<the owner''s message>' } | ConvertTo-Json | Set-Content -Encoding utf8NoBOM (Join-Path $env:TEMP 'dv3-idle.json')
```

Nobody else writes it, and no task, test or check creates it, `dv3-sudoku-seen.txt` or a lock file in the real
`$env:TEMP`. The helper uses 15 s only while the file parses with that format, `setAt <= now < idleUntil`,
`idleUntil - setAt <= 24 h`, and no pentomino helper has seen `dv3-sudoku.lock` since `setAt` (it writes the time it
last saw that lock to `$env:TEMP\dv3-sudoku-seen.txt`); it uses 45 s in every other case. It reads the declaration with
`ConvertFrom-Json -DateKind` (PowerShell 7.5 or later; an older PowerShell gives 45 s) and accepts ISO 8601 times only.
It rechecks the declaration on every pass of a wait and once more before it starts node; from the first failed check,
and from any sight of the Sudoku lock (in a wait or at the collision check after it acquires its own lock), it uses
45 s for the rest of that invocation, and a short quiet found invalid after acquiring releases the lock and waits the
full 45 s (T11h step 1e). No statement, an unknown, expired or unreadable declaration and one contradicted by a
difficulty-v3 run all fail closed to 45 s, which only costs time. The runner counts the quiet actually waited, at most
45 s (§1); prices and budget decisions reserve 45 s per invocation (T11h).
